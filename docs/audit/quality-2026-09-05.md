# Revisión del 5 de septiembre de 2026

Base: `origin/feat/optional-remote-tools`, commit `5cb703c`.
Rama de trabajo: `fix/memory-and-runtime-quality`.

## Memoria

El botón dependía del resultado de un modelo y no conservaba la respuesta
original. Consultaba 20 turnos mientras la UI podía mostrar 40, y los trabajos
encolados dependían del historial disponible al ejecutarse. El cliente podía
seguir sondeando sin límite. En el arranque local de Electron, el guardado HTTP
tampoco usaba la autenticación del puente que sí usa la conversación.

Ahora se guarda el original antes del destilado y se puede consultar en Sistema.
El contexto pendiente sobrevive a cambios de conversación y reinicios. El
seguimiento tiene límites, los errores se comunican y las capturas repetidas
reutilizan su trabajo. Ver [contrato de memoria](../architecture/improvements-memory.md).

## Compilación

Las huellas incluyen STT, TTS, servicios remotos, scripts compartidos y la versión
de Bun. Excluyen pruebas y podan `node_modules` antes de recorrerlo. Las rutas
opcionales ausentes ya no hacen fallar `find` bajo `pipefail`. Los nombres con
espacios se procesan con separadores nulos.

Medición local del hash de red, cinco ejecuciones por variante con dependencias
instaladas: 1.375 archivos y mediana de 43,8 ms antes; 8 archivos y 15,0 ms después.
Esto mide el cálculo de esa huella, no la construcción de una ISO.

## Dependencias

- Electron pasa de 37.10.3 a 42.11.2, una de las ramas estables publicadas en
  [Electron Releases](https://releases.electronjs.org/). Los scripts de empaquetado
  ejecutan `install:electron` para descargar el runtime, ya que esta versión
  no lo instala mediante un postinstall del paquete.
- Pi pasa de `@mariozechner` 0.73.1 a `@earendil-works` 0.79.0. Se mantienen las
  rutas de credenciales y sesiones de AgenOS. La nueva distribución corrige
  [escrituras de credenciales](https://github.com/earendil-works/pi/security/advisories/GHSA-r95r-rj6r-c39x)
  y [carga de recursos de proyectos](https://github.com/earendil-works/pi/security/advisories/GHSA-mqxh-6gq7-558m).
- Se fija Pi en 0.79.0 para mantener la API de integración. La versión 0.80.8
  eliminó `AuthStorage` y cambió `createAgentSession` a `ModelRuntime`; actualizar
  a 0.85.0 requiere migrar autenticación y selección de modelos.
- Se actualizan las demás dependencias dentro de sus rangos y se fuerza Undici
  8.9 o posterior dentro de la rama 8, pues Pi fijaba una versión vulnerable.

`bun audit --json` pasó de 90 avisos en 19 paquetes de la UI y 89 avisos en 18
paquetes del instalador a cero avisos en ambas aplicaciones. Es el resultado de
la base de avisos consultada en esta fecha, no una garantía sobre todos los
componentes de la distribución Linux.

## Validación

- Compilación de producción y comprobación TypeScript de las dos aplicaciones.
- `make test`, con las suites de UI, instalador, agente, STT, TTS, servicios
  remotos, Python y huellas de compilación.
- Pruebas nuevas de persistencia del original sin modelo, reinicio sin historial,
  búsqueda y borrado, fallos de fusión, captura por IPC y espera acotada.
- Se corrigieron los dobles CDP de las pruebas de control web: faltaba un nivel
  `result`, la excepción estaba fuera de su respuesta y la creación de pestañas
  dependía de una microtarea ajena a `/json/new`.

El runtime de Electron se descargó correctamente para las dos aplicaciones.
El intento de abrir una ventana con Ozone headless no pudo inicializar EGL/X en
este entorno y terminó con SIGSEGV; no se considera una prueba gráfica superada.

No se ha construido una ISO completa ni probado el portátil físico. Tampoco se
ha hecho un inicio de sesión real o una petición de destilado a un proveedor.
Las pruebas verifican la integración con respuestas controladas.
